# Repository architecture

## Current executable tooling

The repository contains metadata, source-provenance, workflow, dependency-alignment, documentation, inventory and preflight controls, plus native-tool bootstrap. Commands inspect fixed declared scopes; received metadata cannot choose another policy or grant build eligibility. The foundation remains under qualification.

## Planned build-evidence boundaries

| Component | Responsibility | Required evidence |
| --- | --- | --- |
| Pin admission | Complete source, generated/dirty inputs, tools, patches, IP, target, settings and portable environment | Exact source/tool identities and a separately admitted detached seal |
| First Libero adapter | Actual version-specific commands, stages, raw reports and final programming artifact | Installed/licensed real format, worker and build qualification |
| Attempts and capture | Unique bounded attempts with complete required outputs and truthful failure | Original raw bytes, exit/outcome, times and complete population |
| Exact metrics and gates | Finite decimal-to-rational conversion, units, complete cohorts and external policy/baseline | Independent arithmetic, raw equality and edge/refusal evidence |
| Rebuild comparison | Compare two existing actual attempts under admitted pin and scope | Final raw bytes/digests and prior authority for explained divergence |
| Build history | Native predecessor/sequence, CAS, replay/conflict and external completeness | Actual persistence/recovery plus trusted genesis/head/range/attempt population |
| Evidence consumers | Installed provider and actual versioned source/consumer interfaces | Real producer/consumer qualification and visible eligibility limits |

The planned native entry has fifteen required root fields: schema_id, claims, source_ref, environment_ref, pinning_manifest_ref, inputs, chain, outcome, bitstream_ref, tool_report_ref, tool_reported, rebuild, policy, gates and unsealable_context.

The seven planned public operations are pin, run, rebuild-check, ledger append, ledger inspect, ledger verify-chain and gate. The command is not installed or registered. Recording a failed attempt can complete successfully; CI acceptance separately requires passing gates and complete history. Inspection has no evaluation authority.

WNS is signed time, selected TNS is nonpositive time and model power is nonnegative watts. Complete clock/corner/path/resource/capacity cohorts remain explicit. Missing values are not zero; model power is not physical energy. A consistent history prefix is not complete history. Rebuild comparison performs no build. Read [validation tooling](validation-tooling.md) for current executable interfaces.
