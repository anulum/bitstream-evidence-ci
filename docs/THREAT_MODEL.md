# Data and authority boundaries

## Present tooling

The maintained checkout and selected development environment are execution inputs for repository controls. Received descriptors, dependency receipts and generated inventories cannot nominate acceptance policy or executables. Checks inspect bounded local scopes and report fixed diagnostics. Byte identity is not numerical correctness, current trust, global registration, reproducible-build proof or hosted qualification.

A source inventory is not a concurrent filesystem snapshot or a power-failure durability guarantee. Native child processes use maintained finite argument vectors and direct-child deadlines; completed-output limits are not live volume ceilings. Full foundation qualification remains in progress.

## Future build inputs

Source inventories, vendor reports, pins, raw programming artifacts, ledger entries and explanations are supplied data. They do not grant program execution, signing, publication, licence access or device authority. Actual admitted driver/tool identities, finite limits, input/output paths and required report populations must be checked before execution or allocation.

A missing report is not zero, stale output is not a fresh attempt and failed capture cannot become a successful build. Model power does not become physical energy. Self-consistent hash links do not establish trusted history completeness. Recording failure does not grant release acceptance. A free-text explanation cannot retroactively authorise a divergent rebuild.

Installed provider compatibility, vendor execution, report interpretation, independent rebuild and durable concurrent ledger behavior remain unimplemented domain boundaries. No runtime isolation, numerical reliability, device control or operational recovery guarantee is claimed.
